# M3 history: dynamic code

**Scope:** milestone M3 — C2 dynamic code: `java.lang.reflect.Proxy`,
`ClassLoader.defineClass`, `MethodHandles.Lookup.defineClass`, Spring CGLIB enhancement,
Objenesis instantiation, `Unsafe` U0, generated-class verification, Spring AOP and the
C2 gate.
**Closed:** 2026-11-25.
**State:** the authoritative slice table, commands and counts are in
[`PROJECT.md`](../../PROJECT.md). This note records the path, the blockers and the
lessons.

## What M3 had to connect

M2 ended with a real Spring `AnnotationConfigApplicationContext` but explicitly set
`proxyBeanMethods = false`: its `@Configuration` class stayed out of CGLIB, and no AOP
proxy existed. M3 had to turn the M2 loader/reflection/interpreter seams into a runtime
that can:

- define a generated class from bytes, verify it, and execute it through the one frame
  model;
- implement a real `java.lang.reflect.Proxy` rather than a special heap object;
- give `ClassLoader` and `MethodHandles.Lookup` their real identity and access paths;
- make the audited `Unsafe` U0 surface honest and reachable through reflection;
- run Spring's repackaged CGLIB/ASM and Objenesis unmodified against the pinned jars;
- run Spring AOP in both JDK-proxy and CGLIB-proxy modes;
- prove the whole set with one C2 gate and an `Unsafe` call log containing only U0.

The final gate is
`RAVA_C2_ACCEPTANCE=1 cargo test -p rava-cli --test c2_gate`; it runs the real Spring
context, CGLIB, Objenesis, `Proxy` and AOP paths and asserts their stdout byte-for-byte.

The M3.1 slice is the architectural seam: every later generated class goes through
`Shared::define_class`, so the same verifier runs for `Proxy`, CGLIB, `Lookup.defineClass`
and `ClassLoader.defineClass`. There is no second class table and no verification bypass.

## The CGLIB blocker chain

M3.6 did not add a CGLIB-specific generator. It ran the real repackaged CGLIB/ASM and
fixed the next real library gap each time. The first probe stopped at
`StringBuilder.append(CharSequence, int, int)`; after that the chain was:

| Order | Symptom | Root cause / fix |
| :--- | :--- | :--- |
| 1 | `StringBuilder.append(CharSequence;II)` no bytecode | Missing native: JDK substring semantics for String/StringBuilder/StringBuffer/null, with typed bounds errors. |
| 2 | `WeakHashMap.<init>()` no bytecode | CGLIB's cache uses a WeakHashMap; registered as a map container (strong entries until M5 references). |
| 3 | `FutureTask.<init>(Callable)` no bytecode | CGLIB's LoadingCache wraps generation in FutureTask; added the single-threaded heap shape and re-entrant run/get. |
| 4 | Bootstrap static argument rejected | `REF_getField` in a BootstrapMethods entry was not resolved; the class-file parser now resolves field handle arguments. |
| 5 | `EnhancerKey.hashCode()` fails | A record's `ObjectMethods` hash was missing; implemented record hashCode and `AbstractList.hashCode`. |
| 6 | CGLIB refuses "runtime enhancement not supported on native image" | M2 advertised `org.graalvm.nativeimage.imagecode=runtime` to avoid JPMS. Removed the lie; added a generated empty `SystemModuleFinder` so Spring's module scan has a truthful answer. |
| 7 | `ClassEmitter.hookCounter` "no static field" | Statics table was empty before initialization; declared static fields now resolve to their default or `ConstantValue` (JVMS §5.4.2). |
| 8 | `Method.getExceptionTypes()` no bytecode | Added the native over `Exceptions` metadata. |
| 9 | `AbstractSequentialList` missing in hierarchy walks | The C1 tree is not closed under superclasses; the VM tolerates an omitted superclass instead of returning a wrong answer. |
| 10 | `Arrays.sort([I)` no bytecode | Added primitive sorts and numeric comparison for the analyzer path. |
| 11 | `BitSet.<init>`/`set`/`get` no bytecode | Added the minimal BitSet shape CGLIB's emitter uses. |

Objenesis initially looked like it would work because `java.vm.name=rava` selects
`Unsafe.allocateInstance`, but the reflective `UnsafeUtils.getUnsafe()` path still failed:
the C1 stubs omit private members, so `Class.getDeclaredField("theUnsafe")` threw, and
`Field.get(null)` for a static field was unsupported. M3.5 added VM-installed static
reflection (the statics table is a declared-field fallback) and static `Field.get`/`set`.
The final Objenesis proof is `value=0`, `marker=7`, with `allocateInstance` in the U0 log.

## Spring AOP and the gate

M3.7 added a real `AnnotationConfigApplicationContext` with `proxyBeanMethods = true`.
The configuration bean is a `$$SpringCGLIB$$` subclass and its `greeting()` calls the
enhanced `hello()` bean. It also runs:

- a bare CGLIB `Enhancer` with a `MethodInterceptor`;
- `ObjenesisStd.newInstance`;
- a JDK `Proxy` with an `InvocationHandler`;
- Spring AOP `ProxyFactory` in the default JDK mode (`Proxy.isProxyClass` true) and in
  `setProxyTargetClass(true)` CGLIB mode (`$$SpringCGLIB$$` true).

The captured stdout is byte-identical to stock JDK 25 on the same classpath:

```text
config-enhanced:true
greeting:hello!
cglib:cglib:hello
objenesis-value:0
objenesis-marker:7
jdk-proxy:proxy:greet
jdk-proxy-class:true
aop-jdk:aop:hello
aop-jdk-class:true
aop-cglib:aop:hello
aop-cglib-class:true
```

Two findings from that slice are easy to miss:

- Spring's repackaged CGLIB uses `$$SpringCGLIB$$`, not `$$EnhancerBySpringCGLIB$$`;
  the bare `Enhancer` probe still uses `$$EnhancerByCGLIB$$`.
- `c2_gate` skips in an ordinary checkout without `compat/jars`; the milestone command
  sets `RAVA_C2_ACCEPTANCE=1`, which turns a missing fetched jar into a failure. A
  skipped C2 acceptance is not evidence for M3.

## Lessons

### 1. Verify at the one definition point

Putting the verifier in `define_class` rather than in the Proxy or CGLIB code made every
generated path pass the same gate. Every later slice could rely on it. If a generated
class is rejected, fix the verifier or the generator, never add a bypass.

### 2. A proxy must be a real class

`Proxy` is a generated subclass of `java.lang.reflect.Proxy`, not a special heap object.
That is why `getClass`, `getInterfaces`, reflection and the CGLIB/AOP interop paths work
without a second identity model. The private `rava/proxy/ProxySupport` helper carries the
reflective `Method` lookup; it is a runtime class, not a change to the C1 `Proxy` stub.

### 3. The audited `Unsafe` surface was blocked by reflection, not by Unsafe

The U0 natives were small; `getDeclaredField("theUnsafe")` and static `Field.get` were the
actual blockers. Implement the observable reflection path, not just the native method.

### 4. Do not advertise a false platform

The GraalVM native-image property was convenient for M2 but made CGLIB refuse runtime
enhancement. Replacing it with a truthful empty `ModuleFinder` exposed more Spring code
and was the right direction. Compatibility properties are part of the contract, not a
switch for the VM's convenience.

### 5. CGLIB needs library breadth, not a second VM

The CGLIB fix list is a sample of ordinary JDK methods (StringBuilder, WeakHashMap,
FutureTask, Arrays.sort, BitSet, Collection, `FileNotFoundException`). Each gap should be
fixed generally and tested at the lowest tier; a native shortcut for `Enhancer.create`
would have made the C2 gate a lie.

### 6. A named marker is version-specific

The task text's `$$EnhancerBySpringCGLIB$$` is not what Spring 6.2.19 emits. The probe
was checked against stock JDK 25 before the assertion was written. Verify naming and
output against the pinned reference, not from memory.

## Still fragile

- **Mixed long/double local slots (fixed post-M3).** M3.7's probe returned the wrong value
  because the interpreter bound arguments compactly while the verifier counts JVM slots.
  Post-M3 issue #52 now binds by descriptor slot and rejects a read of a wide value's
  reserved second slot (`cargo test -p rava-interp --test slot_layout`).
- **`Class.getFields` (fixed post-M3).** Issue #53 added the inherited public-field array
  in JDK order. The C1 tree is still not closed under superclasses: 69 platform owners are
  absent from the transitive closure (35 direct superclass names over 44 edges), and the
  reflection walks end that branch at `ClassNotFound`. The tolerance and counts are
  documented in `docs/explanation/c1-metadata.md`; no tree regeneration was made.
- **C2 gate depends on fetched jars.** `compat/jars` is not committed. The local gate
  must set `RAVA_C2_ACCEPTANCE=1`; CI without the jars skips the acceptance.
- **Access control and modules are thin.** There is no real access check,
  `ProtectionDomain` is null, the module layer is an empty `ModuleFinder`, and
  `ClassLoader` resources exist only as empty stubs.
- **`Unsafe` is U0 only.** U1+ methods fail loudly; direct buffers have no storage or
  address, and `invokeCleaner` is a no-op.
- **Proxy limits.** No access checks, no `UndeclaredThrowableException`, and the
  `ClassLoader` argument is ignored. Generated methods now load parameters at JVM slot
  indexes (post-M3 #52).
- **CGLIB/ASM limits.** Record `equals`/`toString` call sites, `FutureTask.cancel`/timed
  get and the rest of `BitSet`/`ModuleFinder` remain unimplemented; advice
  chains/pointcuts and `@AspectJ` auto-proxying are outside the gate.
