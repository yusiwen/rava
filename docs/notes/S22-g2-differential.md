# S22 — G2: printing compared with the reference launcher, byte for byte

- **Slice:** S22
- **Requirements:** G2
- **Acceptance:** `cargo test -p rava-cli --test print_differential` exited 0 on 2026-11-20
  (1 test: compile with the host `javac`, run with `java` and with `rava run`, compare stdout,
  stderr and the exit code).

## What surprised me

**The comparison caught a real bug on its first run.** `rava` printed `恏絙` where `java` printed
`你好`: every non-Latin-1 string was byte-swapped. S10 stored UTF-16 with
`char::to_be_bytes`, but JDK 21's `StringUTF16` stores a char in the **host's** byte order and
asks its `isBigEndian()` native which order that is. The native was missing until this slice;
S21's ASCII tests never touched the path, and S10's own fixture used `"hello"`.

**A differential test needs almost no infrastructure.** The sample is written to a temp
directory, compiled by the host `javac`, and run by both launchers; there is no corpus to commit
and no golden file to maintain — the reference launcher *is* the golden file.

## What the specification says

G2 asks for "a program that writes to `System.out`, with its bytes compared to the reference
launcher, byte for byte". The comparison covers the whole stack that matters here: the program's
bytecode, the VM's `println` overloads, the charset encoder, `FileOutputStream.writeBytes`, and
the CLI's stdout write.

## The bug I hit

The UTF-16 byte order described above. `StringUTF16.isBigEndian()` now answers `false` for this
little-endian host, and `encode_string`/`decode_string` use `to_ne_bytes`/`from_ne_bytes`.

## Open threads

- `System.in` is not installed; `printf`/`Formatter` are untested (the sample uses `print`/
  `println` only).
- Stack traces are compared by content in S21's test, not byte for byte; a `printStackTrace`
  differential would pin `StackTraceElement` formatting and line numbers.
- The sample is generated by the test rather than kept in a corpus; if more programs need
  differential testing, a `samples/` directory and a golden runner are the next step.
