# M2 history: C1 metadata and the first Spring context

**Scope:** milestone M2 — C1 metadata, minimal class library, and a real Spring
`AnnotationConfigApplicationContext` bean graph.
**Closed:** 2026-11-24.
**State:** the authoritative slice table, counts and dates are in
[`PROJECT.md`](../../PROJECT.md). This note records the path and the lessons.

## What M2 had to connect

M2 started from M1's static surface: 35 pinned jars, a manifest, and a synthetic link
stub tree. It had to turn that into:

- a JDK-17-shaped metadata tree with a normalized C1 diff;
- a runtime that loads those class files, creates class/member/annotation/generic
  objects, and executes real Spring code;
- enough library behaviour that Spring's context can start and return a bean.

The final smoke is a real context with `proxyBeanMethods = false`, one `@Bean String
hello()`, and `ctx.getBean(String.class)` printing `hello\n`.
The mechanism is explained in
[`spring-context.md`](../explanation/spring-context.md); the gate interpretation is in
[`compatibility-gates.md`](../explanation/compatibility-gates.md).

were fixed by the slices that followed it.

## The Spring blocker chain

The first attempt at M2.23 got much further than expected, then exposed a chain. The
table records the first **new** blocker after each step; a step often fixed several
smaller gaps before revealing the next one.

| Order | Symptom | Root cause | Fix / slice |
| :--- | :--- | :--- | :--- |
| 1 | `LinkedHashSet.<init>(I)V` has no bytecode | C1 stubs have no `Code`; no native for the constructor | Spring WIP/M2.23: add the collection/reflection/monitor surface; first `monitorenter` then followed. |
| 2 | `StreamSupport.stream(Spliterator, boolean)` has no bytecode | Eager streams/Spliterator/Collectors absent | M2.24: stream pipeline, spliterators, collectors, Optional, re-entrant callbacks. |
| 3 | `Byte.valueOf(B)Byte` has no bytecode | Only `Integer` was boxed; `BeanUtils.<clinit>` boxes every primitive | M2.25: all eight boxes, Number accessors, widening/unboxing, boxed text. |
| 4 | `CachingMetadataReaderFactory.setCacheLimit(I)V` with `metadataReaderCache` null | `instanceof(null)` pushed 1, but JVMS §6.5 requires 0; a test had pinned the wrong result | M2.26: fix `instanceof` null; correct the M2.21 test; then `LinkedHashMap(IFZ)` access order. |
| 5 | `java/lang/annotation/ElementType not found` | The manifest scan recorded constant-pool owners but not descriptor/signature/annotation-only types | M2.27: descriptor closure, 980 → 1,047 classes; regenerate both trees; 36 placeholders. |
| 6 | `Method.isBridge()Z` has no bytecode | C1 stub member had no native | M2.28: bridge/varargs/synthetic flags, plus collection/callback fixes. |
| 7 | `MessageFormat.<init>(String)` has no bytecode | `AbstractMessageSource` initializes a `MessageFormat` | M2.29: minimal MessageFormat/StringBuffer; `AccessibleObject` and collection fixes. |
| 8 | `Class.getMethod("close")` returned null, then `Method.getName()` on null | Named-lookup misses returned null instead of the JDK exceptions Spring catches | M2.30: real `NoSuchFieldException`/`NoSuchMethodException`, `getClasses`, shutdown-path collection/event/record fixes. |

The Spring rerun also caught a `computeIfAbsent` re-entrant heap-lock deadlock
(`keys_equal`/`find_key` locking the heap again), fixed in M2.26. That bug is a good
example of why the no-lock discipline is tested rather than assumed.

## Lessons

### 1. A wrong test can protect a spec bug

M2.21 added a test asserting `instanceof(null) == 1`. It passed, and it hid the bug until
Spring's `metadataReaderCache` null took the wrong branch. The fix changed both the
interpreter and the test. A test that encodes a wrong specification is worse than a
missing test because it creates false confidence.

**Re-check:** when a new integration path contradicts an existing unit test against the
JVMS/JDK, suspect the test first; update the test and the code in the same change.

### 2. Static scans need descriptor closure

The M1.2 manifest was built from constant-pool references. That is not enough:
`ElementType` appeared only as an annotation enum value/descriptor, and
`CachingMetadataReaderFactory` needed a type that was never a `CONSTANT_Class` owner.
The manifest now closes over member descriptors, signatures and annotation-encoded
types; the surface grew 980 → 1,047 classes.

**Lesson:** an observed-surface manifest should be defined by **types used**, not only
types named in constant-pool refs. Re-baseline both stub trees and all counts in the same
change.

### 3. Metadata tree and behaviour must stay separate

C1 stubs are class files with real metadata but no `Code`. The native registry is
consulted before `Code`/`ACC_NATIVE`. This made it possible to add Spring-required
methods incrementally without inventing bytecode or copying JDK implementations.

**Lesson:** do not “fix” a missing C1 method by putting a fake body in the stub; add a
native (or a real library implementation) and a test. Keep the metadata tree generated.

### 4. JDK exceptions are part of the API

Returning `null` from `Class.getMethod` looked convenient, but Spring catches
`NoSuchMethodException` and falls back to `"shutdown"`. Null changed control flow and
crashed later. M2.30 now throws real exception objects from all six named lookups.

**Lesson:** when the JDK contract throws, the runtime must throw a catchable object, not
a typed Rust error or null, if the target framework observes it.

### 5. Re-entrancy and locks are easy to get wrong

`computeIfAbsent` held the heap lock and then called `keys_equal`, which tried to lock
the same heap again. On a single thread this is a futex hang, not a compile error.
M2.26 changed the helper to take `&Heap`.

**Lesson:** native callbacks that re-enter the VM must not hold a heap/class-table lock.
The lock probe at Java call boundaries is a backstop, not a proof for every native path.

### 6. Class identity and loader delegation are not incidental

The C1 tree is bootstrap; the application classpath is a child loader; parent-first
delegation means an app copy cannot shadow a library class. The Spring run and the
loader tests both depend on this. Treating classes by bare name would have hidden
duplicate `Object`/`String` identities.

### 7. UTF-16 and modified UTF-8 are separate concerns

Strings are UTF-16 at the Java-visible layer; class-file constant strings are modified
UTF-8 (CESU-8 style), not standard UTF-8. The M2.9 work exposed the encoder, and
supplementary characters needed both the UTF-16 APIs and the class-file writer fix.

### 8. CI and local gates are different products

`cargo xtask ci` runs without a JDK or fetched jars. The Spring test and `compat`
commands are opt-in/local. A skipped Spring test is not C3 evidence. The M2 green is
`cargo xtask ci` **plus** the local Spring and compat commands, recorded separately.

### 9. Keep a visible blocker list

The Spring run was advanced by fixing the **first** concrete blocker repeatedly. The
temptation is to fix a batch speculatively; that makes it hard to attribute a regression.
The M2.23–M2.30 chain is the record of doing one blocker at a time, with a test for each
fix.

### 10. Branch and commit hygiene needs the same discipline as code

One slice plan was briefly committed on `main` and had to be moved to a feature branch;
another branch was created before the previous slice's work was committed. Both were
recoverable, but they show that the ledger/docs workflow is part of correctness here:
branch before commit, keep the slice's code/docs/tests together, and verify the base
before starting the next slice.

## Still fragile after the M2 green

These are deliberately carried forward; they are not hidden by “M2 done”:

- **C1 is qualified:** 1,011 classes have a release-17 `ct.sym` reference; 36 manifest
  owners are placeholders excluded from the diff. It is a normalized class-file diff,
  not a live JDK 17 reflection differential. See
  [`c1-metadata.md`](../explanation/c1-metadata.md).
- **The Spring smoke is minimal:** one `@Bean`, one class, `proxyBeanMethods=false`, no
  Boot web app, no CGLIB/component-scan/breadth.
- **C2/C4 are absent:** `Proxy`/CGLIB/Objenesis/`Lookup`/`Unsafe` U0 and the reference
  Boot web app are later milestones.
- **No full C3 API suite:** collections, I/O, NIO, networking, resources and
  `ServiceLoader` are manifest-driven and incomplete.
- **Reflection is partial:** no `Parameter`, record/sealed reflective views, complete
  annotation/type-annotation reflection, access checks or full JDK differential.
- **No stack traces/finally/`InvocationTargetException` wrapping**, and one local slot
  per `long`/`double`.
- **Dependency review:** `regex` was added for `java.util.regex` during the Spring
  blocker chain; check it against the dependency policy before treating it as settled.
- **Fixture drift:** committed `.class` fixtures are reproducible from source, but CI
  does not rebuild them; a source/class mismatch is caught only by review.
