# ADR-0003 — The compatibility contract is an observed surface manifest

- **Status:** accepted (2026-11-23)
- **Date:** 2026-11-22
- **Supersedes:** —
- **Superseded by:** —

## Context

"We support Java 17" is not a testable requirement. The Java SE API is far larger
than any first application needs, and the parts a framework reaches are a small,
measurable subset. Two failure modes follow from guessing the subset: implementing
thousands of members nobody calls, or missing one member that only appears on an
error path.

The contract needs to be derived from the target and versioned with it, so that a
change in the application or the framework is visible as a manifest change rather
than as a production surprise.

## Decision

The scope is an **observed surface manifest**, produced from the pinned target
(ADR-0002):

1. **Static scan.** Parse every jar in the pinned classpath and record every
   constant-pool reference to `java/`, `javax/`, `jdk/` and `sun/` as
   `(owner, name, descriptor)`.
2. **Dynamic class loading.** Run the reference application on JDK 17 with
   `-Xlog:class+load=info` (or `-verbose:class`) and record the loaded classes.
3. **Reflective access.** Record the classes and members reached through
   `Class`, `Field`, `Method`, `Constructor`, `MethodHandles`, `VarHandle` and
   `Unsafe`. The mechanism is an agent/JFR/VM shim decision made during M1; the
   manifest must include it.
4. **Metadata.** Record annotations, generic signatures, record components, sealed
   hierarchies and parameter names read by the application.

The union is committed as a versioned file (for example
`compat/surface-<target>.txt`) together with counts. It is both the scope and the
gate:

- Members in the manifest must exist with matching descriptors and behaviour.
- Members outside it are not promised and may fail with `NoClassDefFoundError`,
  `NoSuchMethodError` or `UnsupportedOperationException`.
- A new application or framework version regenerates the manifest and reopens the gap
  count.

The **compatibility levels** turn the manifest into gates:

| Level | Definition | Gate |
| :--- | :--- | :--- |
| C0 — Link | Every symbolic reference resolves; classes load, link and verify | `rava link-check` unresolved = 0 |
| C1 — Metadata | Reflective shape equals JDK 17 for manifest classes | normalized metadata diff = 0 |
| C2 — Dynamic | Proxy, `defineClass`, CGLIB/Objenesis, `Lookup`, declared `Unsafe` subset, generated classes verify | C2 test suite exits 0 |
| C3 — Runtime | Collections, concurrency, time, I/O, NIO, networking, charsets, regex, `java.beans`, jars/resources, `ServiceLoader` | API tests and Spring context exit 0 |
| C4 — Framework | Reference Boot web app and selected Spring tests | HTTP suite, Spring subset, JCStress exit 0 |

## Alternatives

| Alternative | Why rejected |
| :--- | :--- |
| Implement the Java SE 17 API in full | Unbounded; the resulting project would spend its budget on unused members and lose the feedback loop. |
| Use only a static scan | Misses reflection, `ServiceLoader`, resources and generated bytecode, which are exactly where frameworks break. |
| Use only a dynamic run | Misses error paths and lazily referenced members; the first production failure is then outside the contract. |
| Define scope by JDK modules | Module boundaries are too coarse (for example `java.desktop` contains both `java.beans`, needed, and AWT, not needed). The manifest is package- and member-level. |

## Consequences

**Positive**

- Scope is a number: classes, members, unresolved references, metadata diffs.
- The contract is versioned with the target; a framework bump is an explicit
  re-baseline.
- Failures point at a missing manifest entry, which is actionable.

**Negative / accepted costs**

- **Closed-world assumption:** unexercised paths can still be reached. The Spring
  test subset (R10) and failure attribution (R11) bound this; it cannot be eliminated.
- The manifest tooling is itself a project (scan, agent/JFR, normalization, diff).
- Manifest churn on every version bump; the team must budget for re-baselining.

## Evidence

- M1 exits 0 with a reproducible manifest and `unresolved = 0`.
- The manifest generator is deterministic; ordering and synthetic members are
  normalized and the normalization is committed.
- The diff between two target versions is reviewed before the target is bumped.
