## M4.1 — Classpath resources: directory/jar lookup and enumeration, `ClassLoader`/`Class` resource natives, `file:`/`jar:` URL streams — 2026-11-26

**Acceptance.** `cargo test -p rava-cli --test resources` — exit 0 (2 tests).

**Delivered.**
- `ClassSource` gains `read_resource`/`resource_urls`/`resource_names`; the loader chain is walked parent-first, so first match and ordered enumeration both work.
- `URL`/`URLConnection`/`InputStream` natives open `file:` and `jar:file:…!/entry` resources with no network transport.

**Boundary.**
- No network, no `URLConnection` headers or dates, no nested jars and no custom `URLStreamHandler`; M4.4 adds the Boot layout.

See [`class-loading-and-libraries.md`](../explanation/class-loading-and-libraries.md) §5a.

## M4.2 — `ServiceLoader` over `META-INF/services`, lazy provider iteration and typed configuration errors — 2026-11-26

**Acceptance.** `cargo test -p rava-cli --test service_loader` — exit 0 (9 tests).

**Delivered.**
- `ClassSource::read_resources` returns every copy in classpath order; `ServiceLoader` keeps its service, loader and provider state in an `ObjRef`-keyed table.
- Providers are loaded and assignable-checked eagerly, but constructed lazily on `next`.
- `load`/`load(Class, ClassLoader)` treat a null loader as bootstrap; every failure is typed and names the provider.

**Boundary.**
- One provider name per line; no module layer, `Provider`/`stream`/`findFirst` or `ServiceConfigurationError`.

See [`class-loading-and-libraries.md`](../explanation/class-loading-and-libraries.md) §5b.

## M4.3 — Executable-jar launch: manifest parsing, `Main-Class`, `Class-Path` and `rava -jar` — 2026-11-26

**Acceptance.** `cargo test -p rava-cli --test jar_launch` — exit 0 (13 tests).

**Delivered.**
- `crates/cli/src/jar.rs` reads `META-INF/MANIFEST.MF` (case-insensitive names, continuation lines, typed malformed errors) and resolves `Main-Class`/`Class-Path`.
- `rava -jar` builds the classpath as the executable jar plus its `Class-Path` entries, and shares loader, natives and `main` invocation with `rava run`.

**Boundary.**
- Flat jars only: no `URLClassLoader`, and only `Main-Class`/`Class-Path` are read.

See [`class-loading-and-libraries.md`](../explanation/class-loading-and-libraries.md) §5c.

## M4.4 — Boot nested-jar layout: `BOOT-INF/classes`, `BOOT-INF/lib/*.jar`, nested `jar:` URLs and launcher classpath — 2026-11-26

**Acceptance.** `cargo test -p rava-cli --test nested_jars` — exit 0 (7 tests).

**Delivered.**
- `BootJarSource` indexes `BOOT-INF/classes/` and each `BOOT-INF/lib/*.jar` in lexical order, and emits both nested `jar:` URL forms.
- `rava -jar` detects the layout and substitutes `Start-Class` for a Boot launcher's `Main-Class`; a Boot manifest's `Class-Path` is ignored, as Boot builds it from `BOOT-INF`.

**Boundary.**
- No Boot loader classes, `loader.path`, exec or nested-jar `Class-Path`; `rava run --cp` still treats a Boot jar as flat.

See [`class-loading-and-libraries.md`](../explanation/class-loading-and-libraries.md) §5d.

## M4.5 — Non-web Boot application gate: real `SpringApplication` with `WebApplicationType.NONE` on the pinned jars — 2026-11-26

**Acceptance.** `RAVA_BOOT_ACCEPTANCE=1 cargo test -p rava-cli --test boot_nonweb` — exit 0 (4 tests).

**Delivered.**
- A committed real Boot application (`@SpringBootConfiguration`, `WebApplicationType.NONE`, one `ApplicationRunner` printing `boot:started`) runs on the 35 pinned jars.
- The startup chain fixed general VM and library gaps only, including the `java.time` formatter surface, `java.beans` descriptors and a `run_method` lock re-entry deadlock.
- A native census (`scripts/native-census.sh`) records what the gate exercises: 581 of 2,132 natives at the slice (593 of 2,104 after #80); 109 of the 585 added here, 476 added keys uncalled (#76).

**Boundary.**
- Not `@EnableAutoConfiguration`: Jackson, SSL, message converters and executors stay C3.
- A single-threaded VM, the C1 omissions and the absence of Java stack traces remain the sub-boundaries.
- Post-slice fixes #71/#73/#74/#79 are closed; the remaining partial subsets are #88/#90, named in §5e.
- M5 owns the real-thread semantics of `Thread.start`/`isAlive`, latch/queue blocking, stack traces and `StackWalker`; its slices update `crates/cli/tests/m5_boundary.rs`.

See [`class-loading-and-libraries.md`](../explanation/class-loading-and-libraries.md) §5e.
