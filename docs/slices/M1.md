## M1.1 — Target lock, reference app and pinned jar set — 2026-11-24

**Acceptance.** `cargo run -p rava-cli -- compat target` — exit 0.

**Delivered.**
- `compat/targets.toml` pins Java 17, Boot 3.5.16, Spring 6.2.19, Tomcat 10.1.55 and 35 jars.
- The reference app builds at `--release 17`; a clean refetch reproduces all 35 sha256 entries.

**Boundary.**
- Validates the lock's shape and jar count; it does not hash the jars.
- `bash compat/fetch-jars.sh --check` does the hashing; the manifest scan is M1.2.

See [`compatibility-gates.md`](../explanation/compatibility-gates.md).

## M1.2 — Static manifest over the pinned jars — 2026-11-24

**Acceptance.** `cargo run -p rava-cli -- compat manifest --check` — exit 0.

**Delivered.**
- A static manifest of 1047 classes, 177 fields, 3,626 methods and 1,048 interface methods.
- Scanned from all 11,754 `.class` entries; deduplicated, sorted and byte-reproducible.

**Boundary.**
- The static half of ADR-0003 only: a lower bound on the surface, not the contract.
- M2.27 widened the scan to the descriptor, `Signature` and annotation-type closure.
- Multi-release entries are scanned as they appear; no version selection is applied.

See [`compatibility-gates.md`](../explanation/compatibility-gates.md).

## M1.3 — Stub library surface and zero-unresolved link-check — 2026-11-24

**Acceptance.** `cargo run -p rava-cli -- compat link-check` — exit 0.

**Delivered.**
- `rava compat stubs` writes 1047 signature-only class files from the committed manifest.
- Link-check resolves 1047 classes and 4,851 member records with `unresolved 0`.

**Boundary.**
- Signature-only and synthetic: every class extends `Object`, non-constructors have no `Code`, and C1 metadata is not claimed.
- Link-check reads the manifest and the stubs only; it never reads the jars or runs a class.

See [`class-loading-and-libraries.md`](../explanation/class-loading-and-libraries.md) §5.

## M1.4 — Manifest reproducibility and M1 gate review — 2026-11-24

**Acceptance.** `cargo run -p rava-cli -- compat check` — exit 0.

**Delivered.**
- `compat check` composes the four stages: lock, manifest, link-check, stub reproducibility.
- A temporary regeneration of `stdlib/classes` is byte-identical across all 1047 files.

**Boundary.**
- A gate over committed artifacts: it never loads a class and never executes one.

See [`compatibility-gates.md`](../explanation/compatibility-gates.md) §C0.

The target is pinned and checked as a set of 35 jars. A fresh scan regenerates the committed
manifest byte-for-byte at 1047 classes, 177 fields, 3,626 methods and 1,048 interface
methods; every record resolves with `unresolved 0` over 4,851 member records; a temporary
regeneration of `stdlib/classes` matches all 1047 committed files. The stubs are
signature-only. `rava compat check` exits 0, and M2 (C1 metadata, the minimal library and
the Spring context) is next.
