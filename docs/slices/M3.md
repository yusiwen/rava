# M3 slice detail — dynamic code

Per-slice record for M3. `PROJECT.md` § Slices owns the status and the one-line

## M3.1 — Generated-class definition: verify every `Code` method before insertion; decode switches and `wide` — 2026-11-25

**Acceptance.** `cargo test -p rava-cli --test c2_generated` — exit 0.

**Delivered.** `ClassTable::define_class` now verifies every method that carries a `Code` attribute after parsing and duplicate checking but before inserting the class; a verifier failure is `VmError::Verify { class, method, detail }` and leaves the class table unchanged, while a missing `Code` (native/abstract/signature-only stub) is skipped. The verifier decodes `tableswitch`/`lookupswitch` (four-byte alignment from the code start, zero padding, default/low/high or npairs, strictly ascending lookup keys, every case target validated) and `wide` local load/store and `iinc`; `ret` and other modified opcodes stay unsupported. The interpreter decodes the same `wide` forms and carries `u16` local indices and an `i32` increment. The new `c2_generated` suite (5 tests) defines and runs a generated `demo/Generated` with a constructor, field and getter, dispatches dense and sparse switches, stores/loads local slot 256, rejects an under-sized `max_stack` without changing `class_count()`, and still rejects a duplicate `(loader, name)`. The definition-time check exposed fixtures that had relied on invalid bytecode; their slot counts and local initialization are corrected without weakening any verifier rejection. `cargo test --workspace` passes 439 tests; `cargo fmt --all --check` and `cargo clippy --workspace --all-targets -- -D warnings` exit 0; `RAVA_SPRING_ACCEPTANCE=1 cargo test -p rava-cli --test spring_context` still exits 0 with `hello\n`.

## M3.2 — `java.lang.reflect.Proxy` / `InvocationHandler`, generated proxy classes and default-method dispatch — 2026-11-25

**Acceptance.** `cargo test -p rava-cli --test c2_proxy` — exit 0.

**Delivered.** A proxy is a real generated class, not a special heap object: `crates/vm/src/proxy.rs` writes `rava/proxy/$ProxyN` with `ClassBuilder` + `Assembler`, extends `java/lang/reflect/Proxy`, lists the requested interfaces, and defines it through `Shared::define_class`, so the M3.1 verifier checks every generated method. The generated methods box each parameter into an `Object[]`, call `InvocationHandler.invoke` with a `Method` resolved by the runtime-private `rava/proxy/ProxySupport` helper, then unbox the result; `widen(JI)J` covers a category-2 parameter and `greet()` covers `InvocationHandler.invokeDefault`, which lives in `rava-interp::proxy` because it re-enters `run_instance_method`. `Proxy` natives cover the constructor, `newProxyInstance`, `getProxyClass` (cached by `(loader, interfaces)`), `isProxyClass` and `getInvocationHandler`; the null `Class[]` error is typed and defines no class. The committed `crates/cli/tests/fixtures/proxy/` fixture (`javac --release 17`) prints nine facts; `c2_proxy` asserts the exact stdout, verifies the generated class in the table, the cache identity on repeated and duplicate interface lists, and a distinct class for a different interface list. `cargo test --workspace` passes 445 tests; `cargo fmt --all --check` and `cargo clippy --workspace --all-targets -- -D warnings` exit 0; `RAVA_SPRING_ACCEPTANCE=1 cargo test -p rava-cli --test spring_context` still exits 0 with `hello\n`. Gaps: no access checks, no exception wrapping, and the `ClassLoader` argument is ignored. The generated methods now load parameters at JVM slot indexes; issue #52 removed the compact-local exception.

## M3.5 — `Unsafe` U0, VM-installed static reflection, direct buffers and the U0 call log — 2026-11-25

**Acceptance.** `cargo test -p rava-cli --test c2_unsafe` — exit 0.

**Delivered.** `crates/interp/src/unsafe_natives.rs` installs the `sun.misc.Unsafe` singleton and serves U0: `getUnsafe`, `allocateInstance` (class initialization then allocation without a constructor), `invokeCleaner` (no-op), plus `jdk.internal.misc.Unsafe`'s `ensureClassInitialized`/`shouldBeInitialized`/`allocateInstance`; every served call is recorded in `Shared::unsafe_calls`, and a U1+ method still fails loudly. The committed `fixtures/unsafe` fixture and `c2_unsafe` (7 tests) cover the singleton identity, constructor-skipping allocation and class initialization, the jdk initialization queries, direct buffers and the no-op cleaner, the U0-only call log, and the exact Objenesis reflection (`getDeclaredField("theUnsafe")` → `setAccessible(true)` → `get(null)`). ## After the M3 gate — issues #52 and #53

Two defects found after the gate closed. They are not slices; they are recorded here because
they belong to the interpreter and reflection surface M2–M3 built.

**Acceptance.** `cargo test -p rava-interp --test slot_layout` and `cargo test -p
rava-interp --test fields` — exit 0.

**Delivered.** Issue #52 made locals JVM slots: arguments bind by descriptor slot, a
`long`/`double` occupies two slots, and a load of the reserved second slot is
`InterpError::LocalHole`; the committed `demo.SlotLayoutProbe` fixture and
`cargo test -p rava-interp --test slot_layout` cover `(JI)J`, `(JD)I`, `(JFI)J`, an instance
receiver and wide stores. Issue #53 implemented `Class.getFields` in the JDK's order (own
public fields, superinterfaces recursively, then the superclass; dedup by declaring
class/name/descriptor; empty for primitive and array classes), with the committed
`crates/interp/tests/fixtures/fields` fixture and `cargo test -p rava-interp --test fields`.

**Boundary.** #53 kept the C1 tolerance instead of closing the tree: 69 platform owners are
absent from the superclass/interface closure (35 direct superclass names over 44 edges), and
the reflection walks end that branch at `ClassNotFound` (see
`docs/explanation/c1-metadata.md`). M4 then built resources, nested jars, `ServiceLoader`
and the non-web Boot application on top.
